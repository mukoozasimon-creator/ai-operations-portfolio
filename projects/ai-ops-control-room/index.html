Single sign-on (SSO), System for Cross-domain Identity Management (SCIM) and access lifecycle

Identity decides access before the AI platform does.

Tap a small question mark when a technical term appears. These controls help access follow a person's real work identity and change safely as their role changes.

01

Security Assertion Markup Language (SAML)

A verified work identity reaches the AI workspace through the organization's identity provider, instead of unmanaged credentials.

02

System for Cross-domain Identity Management (SCIM) group mapping

A named group maps to the smallest useful role. The workspace does not decide access on its own.

03

Access lifecycle and exceptions

Joiners can use an approved route. Movers and elevated access wait for an accountable owner. Leavers lose access and reclaim the seat.

Reference route

Identity provider to group to role to audit record.

A functional build connects this control design to the organization's actual provider, platforms and policy owners.

  1. Authenticate: confirmed work identity reaches the platform through single sign-on (SSO).
  2. Map: SCIM uses an approved group and a least-privilege role.
  3. Review: exceptions and changes stop for a named owner.
  4. Remove: offboarding removes access and retains the audit record.

Role-based access control (RBAC) in plain English

People get only the access they need to do useful work.

These demo roles make access understandable. A real implementation uses a clear work reason, named owner, policy check and future review date.

01

Standard

Draft, research and summarize approved work. This role cannot manage people, billing or settings.

02

Analyst

Standard access plus approved workspace analytics and shared project knowledge.

03

Workspace administrator

Manages members and settings. It needs a security owner approval and a review date.

Join, change, leave

Access is a lifecycle, not a one-time click.

  1. Join: verify identity, team, approved purpose and appropriate role.
  2. Move: reassess access when someone changes team, data scope or responsibility.
  3. Leave: remove access, retain the audit trail and reclaim the license.
